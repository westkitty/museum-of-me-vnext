- Phase 1 foundation: the local Workshop save endpoint now retains exact previous manifest bytes in content-addressed, Git-ignored `data/.workshop-backups/` before replacing a valid save. Concurrent saves within one server process are serialized; backup failure prevents replacement. These backups do not yet constitute an automated schema migration, rollback UI, multi-process lock, or media/model backup. Manually restore a selected backup only after preserving the current manifest and checking its referenced local assets.
- Schema v1 validation rejects unsupported fields instead of silently dropping them. The save endpoint refuses to replace an existing corrupt, unsupported-version, or otherwise invalid manifest, preserving its bytes for recovery. The local development page now receives the exact manifest bytes and their SHA-256 as one startup snapshot; the editor sends that byte revision and the server rejects changed bytes under the same-process save lock. Focused tests cover changes lost by schema rounding, and a real Workshop browser test verified a normal save and stale-revision rejection. This does not provide cross-process locking or schema migration.
